# Spec drift audit — `statusline-behaviour.md`

**Date:** 2026-08-23 · **Method:** each spec section validated against the code
by an independent reader; code treated as ground truth throughout.

**Coverage:** complete — §1 through §14.

---

## The shape of the problem

The spec is maintained by **layered strike-through amendments** rather than
rewrites. Nine amendment blocks were counted. The pattern works for recording
*why* a decision changed, but it has a systematic failure mode, and nearly every
finding below is an instance of it:

> **An amendment updates its own section and never revisits the earlier text it
> falsified.** The stale half is almost always the *original* line — which is
> the line a reader reaches first.

The most common concrete form: **the `caps-hook` cycle (`8f4efe0`) added a whole
CLI surface and a whole config block, amended the two sections it was thinking
about, and left four other sections describing a binary that has one fewer
surface than it does.**

Severity below is about *what a reader does wrong*, not about elegance.

## Tier 1b — code defects found during the audit

Not spec drift. Both are real bugs.

### B1 — an empty new env var masks a valid legacy one

`src/modules/usage.rs:29-34`:

```rust
std::env::var(USAGE_DIR_ENV).ok()        // "" → Some("")
    .or_else(|| var(LEGACY_USAGE_DIR_ENV).ok())  // Some("") is Some → never runs
    .filter(|d| !d.is_empty())           // → None
```

`CLAUDE_STATUS_USAGE_DIR=""` with a valid `AI_PLUGINS_USAGE_DIR` returns `None`,
**silently disabling the mirror** — and with it the caps hook's only data
source. Spec `:928` promises "the new name first, the old one still honoured".
The `.filter` must run on each arm, before the `or_else`. Untested.

### B2 — `--debug` never shows the caps-hook wiring

`claude_wiring()` (`src/_runtime/app.rs:436`) reads only `statusLine` and
`subagentStatusLine`, so `--debug` cannot show the `hooks.PostToolUse` key that
the binary's own `HELP` (`cli.rs:34-37`) tells users to wire. The diagnostic
that exists to verify wiring is blind to a third of it.

## Tier 4 — under-specification (omissions, not contradictions)

Behaviour the code pins deliberately, with in-code rationale, that the spec
never records. Each is a place a reimplementer would silently diverge.

**§1 invariants**

- `:104-108` **invariant 3 is stated unconditionally but has two deliberate
  exemptions**: `--subagent` (`app.rs:181-189`) and `--caps-hook`
  (`app.rs:110-118`) panic to **empty output**, because a fallback line would be
  invalid NDJSON / would be injected verbatim into the agent's context. Only
  `--statusline` prints `FALLBACK_LINE`.
- `:92-95` **nothing in §1 says a render writes.** It does, twice: the usage
  mirror (`app.rs:220`) and repo-layer config creation via `autoseed::ensure`
  (`app.rs:76-86,238`). §8 covers the mirror; the config write is
  unforeshadowed.

**§2 payload**

- `:211-213` the token chain has a **deliberate zero asymmetry** —
  `total_input_tokens: 0` is kept, a `current_usage` sum of exactly `0` falls
  through to the derived branch (`payload.rs:131`, rationale `:115-118`,
  reproducing JS `??` vs `||`).
- `:215-216` the string half of `resets_at` is **much narrower than ISO 8601**
  (`_shared/time.rs:40-48`), reads a missing offset as **UTC** (divergence from
  JS local-time), and **rejects a numeric string** (`:23-24`). Also this happens
  downstream, not in the payload layer (`payload.rs:31-34,153`).
- Unmentioned normalisations: `session_name: ""` → absent (`payload.rs:55`),
  `resets_at: null` → absent (`:153`).
- `:222` panel width ladder is `payload.columns → $COLUMNS → 80`
  (`subagent.rs:94-99`); the code comment at `:91` says "the contract mentions
  neither the env var nor the default".
- `:223` panel cwd is `payload.cwd → first task's cwd → process cwd`
  (`subagent.rs:287-297`) — **not** the main bar's rule, and `workspace` is
  never consulted.
- `:232` a task is skipped when `id` is absent **or null**; `id: 0` and `id: ""`
  are kept, and the id keeps its JSON type.
- `:240-241` rows join with `\n` and carry **no trailing newline**; a payload
  with no `tasks` array renders **completely empty** and never falls back to the
  main bar.
- `:248-250` effort with no model renders as a bare `[high]`.

**§3 / §4 / §6**

- `:348-355` an explicit `null` in an override **replaces** (`json.rs:83-85`),
  and forbidden keys are stripped at every depth inside wholesale-replacement
  values (`json.rs:108-122`).
- §3 never pins three coercions: `gauge.width` capped at `MAX_GAUGE_WIDTH=1000`
  and a configured `0` meaning 10 (`config/mod.rs:25,76-81`); empty
  `gauge.empty`/`filled` falling back to the shipped glyph (`:88-91`); empty *or
  invalid* `worktreePattern` falling back and **warning on stderr**
  (`:122-137`).
- `:473-475` a **non-numeric** `descBudgetFraction` falls back to `0.45`
  (`subagent.rs:117-123`) where the JS produced `NaN` and disabled truncation.
- `:506-507` the same-background seam emits **bg before fg**, the opposite of
  the differing-bg branch (`powerline.rs:88-96`). `powerline.rs:3-6` says the
  order is load-bearing — "the same colours on most terminals and the wrong ones
  on some".
- `:499-509` `RESET` is emitted after **every** fragment
  (`powerline.rs:74,85,99,107`), so bold never leaks and a mid-line truncation
  cannot bleed colour into the TUI.
- `:523` an **empty-string** model also falls back to `Claude`, and an empty
  effort drops the `[…]` entirely (`segments.rs:115-117`).
- `:533` the **worktree glyph is conditional too** (`segments.rs:159-161`),
  which the amendment at `:543-545` does not say.
- `:607` the panel sanitizes at **two** points, not one — `subagent.rs:252`

- `:557-558` the megabyte threshold tests the raw value, so `999_999` renders

- `:563-564` gauge `round` is JS `Math.round` — halves toward **positive
  infinity**, not away from zero (`fmt.rs:237-239`).
- `:554-566` lists four helpers; `human_caps_in` (`fmt.rs:163-192`) is an
  output-visible fifth that differs from `human_reset_in` in three tabulated
  ways.
- `:705` "shells out up to **twice**" — up to **three** in that pipeline
  (`git.rs:213-230`), and the spec says "up to four" twelve lines later at
  `:721`. `git.rs:7-10` says four. **§7 spend — under-specified**

- `:853-855` the 24h stretch needs **four** conditions, not the one stated:
  `show=="auto"` AND a cache exists AND `cache.plan` is `Some` and non-empty AND
  not team (`schedule.rs:52-54`). `schedule.rs:24-29` says outright *"the
  contract gives only the conclusion"*. A cache with no plan recorded uses the

- `:807-809` lists **two** lock outcomes; there are three —
  `Acquired::Indeterminate` (`lock.rs:30-35,43,51,61`) for a lock that vanished

  user-visible as `Outcome::LockUnavailable` with its own `--debug` line and

- `:832-834` is silent on `backoffUntil` for 401/network. Only the 429 branch

  calls this "load-bearing".
- `:830-834` lists 429/401/network; the code also has
  `Response::Unexpected(status)` (`http.rs:36,96`), a 1 MiB body cap and a 10 s
  global timeout, both surfacing as `Transport` (`http.rs:23,27,87-90`).
- `cache::path()` returns `None` — not a relative fallback — when `$HOME` is
  unset (`cache.rs:82-86`).

- `:742-743` gives **no hint that `worktreePattern` is a regex**.
  Metacharacter-free patterns are a lowercased *substring* search over
  `|`-alternatives; anything else compiles via `regex_lite`; an invalid pattern
  warns and falls back (`matcher.rs:22-27`, `config/mod.rs:127-133`).
