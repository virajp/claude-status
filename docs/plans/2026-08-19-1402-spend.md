# Plan: spend — 2026-08-19

## Slice

The spend segment and everything behind it — §7 of
[the behaviour contract](../spec/statusline-behaviour.md), plus the `--debug`
modifier from §5. The cache, the lock, the detached refresh child, credential
reading, the one network call, the extraction ladder, backoff, and the four
gates that can hide a perfectly successful fetch.

Plan 3 of 4 — requires [`main-bar`](./2026-08-19-1400-main-bar.md); required by
[`distribution`](./2026-08-19-1403-distribution.md).

Independent of [`subagent-panel`](./2026-08-19-1401-subagent-panel.md) — the
panel never renders this segment. Either order, or concurrently in separate
worktrees.

This is the hard part. Everything else in the contract is mechanical; this is
where the design decisions are, and each was made for a reason recorded below.

## Current state (actual)

After [`main-bar`](./2026-08-19-1400-main-bar.md):

- `render/segments.rs` has a `spend` builder that always returns `None`, so the
  segment is present in the default `lines` but never draws.
- `json.rs::write_json_atomic` exists (temp + rename) and is tested.
- `proc.rs::run_bounded` exists; `spawn_detached` does not.
- `fmt.rs::money` exists and is tested.
- `cli.rs` recognises `--refresh-spend` and `--debug` but `--refresh-spend` is a
  no-op.
- No HTTP dependency in `Cargo.toml`. No `src/spend/`, no `src/debug.rs`.
- No cache is ever read or written; no child is ever spawned.

## Target state (per blueprint)

The account's monthly budget from claude.ai → Settings → Usage, rendered as
`{spend} $75.93/$150 (51%)`. It exists for **team/enterprise** seats, whose
limit is a monthly spend cap rather than the 5-hour and 7-day windows.

**A render must never fetch.** The figure comes from the OAuth usage endpoint
that Claude Code's own `/usage` uses; that endpoint throttles on *accumulated
account usage*, and a tripped account stays 429 for half an hour or more, while
the bar can render every four seconds in every open session. So a render reads a
cache file and nothing else; when the cache is stale it spawns a detached child
and draws the cached value immediately, never waiting.

**Renamed, no migration.** The compatibility surface moves to this repo's name:

|                   | Old (`ai-plugins`)               | New                                 |
| ----------------- | -------------------------------- | ----------------------------------- |
| Cache             | `~/.cache/ai-plugins/spend.json` | `~/.cache/claude-status/spend.json` |
| Cache override    | `$AI_PLUGINS_SPEND_CACHE`        | `$CLAUDE_STATUS_SPEND_CACHE`        |
| Endpoint override | `$AI_PLUGINS_SPEND_URL`          | `$CLAUDE_STATUS_SPEND_URL`          |

The old cache is left in place and ignored; a first run re-fetches once, which
is harmless. **`$AI_PLUGINS_USAGE_DIR` is untouched** — that is a different
contract, owned by §8 and consumed by another repo.

## Delta — ordered steps

Built bottom-up: the two things most likely to be wrong — the extraction ladder
and the gates — are pure functions, fully tested before any I/O exists.

1. **`src/spend/extract.rs` — the ladder, pure.** In order:
   `spend.limit.amount_minor` present → take `spend.used.amount_minor`,
   `spend.limit.amount_minor`, `spend.limit.exponent` (default 2),
   `spend.percent`, `spend.enabled`. Else `extra_usage.monthly_limit` present →
   `used_credits`, `monthly_limit`, `decimal_places` (default 2), `utilization`,
   `is_enabled`. Else `None` — **the account has no budget block**, which is a
   valid outcome, not an error. *Test-first:* one case per rung, plus a body
   that is valid JSON but neither shape, plus a body that is not JSON at all.

2. **`src/spend/mod.rs` — the four gates, pure.**
   `verdict(&Option<SpendCache>, &SpendCfg, &Lines) -> Verdict` returning either
   `WillRender { text }` or `Hidden { gate }`. In order:

   | Gate | Condition                                                                                                                                       | Why it matters                                                                                                                                |
   | ---- | ----------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
   | 1    | `spend` is not an entry in any row of the resolved `lines`                                                                                      | The cache is never read and no child is ever spawned. A user without the segment pays **nothing** — no file read, no fork, no keychain prompt |
   | 2    | no cached `data`                                                                                                                                | Nothing to show                                                                                                                               |
   | 3    | `data.enabled == false` **strictly**, or `limitMinor` is falsy **loosely** (so `0` hides)                                                       | The account reports no usable budget                                                                                                          |
   | 4    | `show == "auto"` (the default) and `plan` is not exactly `team` or `enterprise` (case-sensitive, read from the **cache root**, not from `data`) | Catches most people                                                                                                                           |

   Gate 1 scans every element of every array-valued row for an entry whose id —
   `entry` itself if a string, else `entry.name` or `entry.id` — equals `spend`.
   Non-array rows are skipped. It runs **after** the config merge, so a repo
   layer can enable or disable it.

   Gate 4 is why `show: "auto"` can sit in the shipped defaults without changing
   anything for Pro/Max users. Any value of `show` other than `auto` renders —
   so `"always"` is not special-cased, and `"yes"` renders too.

   Text: `pct = data.percent` if present (so `percent: 0` is honoured), else
   `usedMinor / limitMinor × 100`. *Test-first:* each gate in isolation and each
   in combination; a cache with `data: null`; `limitMinor: 0`; `enabled: 0`
   (which does **not** hide, since gate 3 tests `enabled` strictly against
   `false`).

3. **`src/spend/cache.rs` — the file.** The shape in contract §7: `ts`, `plan`,
   `failures`, `backoffUntil`, `data` (null when the account has no budget
   block). Path resolves `$CLAUDE_STATUS_SPEND_CACHE` (expanding a **leading `~`
   only** — unlike `$AI_PLUGINS_USAGE_DIR`, which also expands `$HOME`; the
   contract conflates the two) else `~/.cache/claude-status/spend.json`.
   Machine-global on purpose: one fetch per interval per machine, however many
   sessions are open. *Test-first:* round-trip; a missing file is `None`, not an
   error; a corrupt file is `None`; `~` expansion; `$CLAUDE_STATUS_SPEND_CACHE`
   wins.

4. **The staleness check and the detached spawn.** On a render, after gate 1
   passes: read the cache, render from it, and *separately* decide whether to
   spawn. `refreshMinutes: 0` disables the spawn entirely, but the cache is
   still read and still rendered.

   **The 24-hour stretch**, stated precisely because the contract gives the
   conclusion without the conditions: the interval stretches to 24 h only when
   `show == "auto"` **and** a cache exists **and** `cache.plan` is truthy
   **and** that plan is not team/enterprise. A cache with **no `plan` recorded**
   uses the normal `refreshMinutes`. It exists because gate 4 hides the segment
   for Pro/Max, but the plan tag itself comes from the same fetch — so the
   machine still re-checks daily in case the seat becomes a team seat.

   Staleness is a strict `>` on both the TTL and `backoffUntil`.

   `spawn_detached` uses `current_exe()` with `--refresh-spend`, all three stdio
   streams null, and `CommandExt::process_group(0)` so the child is not in the
   terminal's foreground group and receives neither the Ctrl-C `SIGINT` nor the
   `SIGHUP` on session teardown. Never waited on — the parent exits in ~1 ms and
   `init`/`launchd` reaps. The child does **not** inherit `--debug`: its stderr
   is `/dev/null`, so narration would be silently discarded. Run
   `--refresh-spend --debug` by hand instead, where stderr is inherited.
   *Test-first:* with a fresh cache no child spawns; with a stale one exactly
   one does; with `refreshMinutes: 0` none does; with `backoffUntil` in the
   future none does; the 24-hour stretch fires only under all four conditions.

5. **`src/spend/lock.rs`.** `<cache>.lock`, created with `create_new(true)`
   (which is `O_CREAT|O_EXCL`). If it exists and its mtime is under 2 minutes
   old, another refresh is running — **exit**. Older than that, the holder died:
   take it over by overwriting non-exclusively. If the `stat` itself fails (the
   lock was just removed), **return without refreshing** rather than retrying —
   faithful to the JS.

   A `LockGuard` whose `Drop` unlinks gives the JS's `finally` for free, and on
   unwind too. Note the asymmetry to preserve: the two early returns in the
   contended path leave the lock alone; the 60-second dedupe return does release
   it. *Test-first:* a fresh lock blocks; a 3-minute-old lock is taken over; the
   guard unlinks on drop and on panic; two concurrent children do not both
   write.

6. **`src/spend/creds.rs`.** `~/.claude/.credentials.json` →
   `claudeAiOauth.accessToken` (required) and `subscriptionType` → `plan`. On
   macOS only, fall back to
   `security find-generic-password -s "Claude Code-credentials" -w`, bounded at
   **5000 ms** — not the 250 ms git budget; the first keychain read may prompt
   the user once. *Test-first:* file path wins; a file without `accessToken`
   falls through; the keychain branch is gated on `cfg!(target_os = "macos")`.
   **Never log the token** — assert that `--debug` output containing the token
   is impossible.

7. **`src/spend/http.rs` — the one network call.** Add `ureq` **3.4.0**,
   `default-features = false`, `features = ["rustls"]`. Named here because the
   plan's approval gate is where new dependencies are consented to.
   - **No async runtime.** There is exactly one request, it runs in a detached
     child, and it may block freely; pulling in tokio would work against the
     startup-time argument that motivates the whole rewrite. ureq's own docs
     state it uses blocking I/O to keep dependencies minimal.
   - **rustls + `webpki-roots`, not native-tls.** `native-tls` on
     `*-unknown-linux-gnu` means `openssl-sys`: OpenSSL headers at build time
     and a versioned `libssl.so` at run time, which would end the single-binary
     distribution story. rustls with baked roots is self-contained and identical
     across macOS and Linux.
   - Set `http_status_as_error(false)` — ureq defaults it to `true`, returning
     4xx/5xx as `Err(Error::StatusCode)`, and the logic here branches on 401 and
     429, so a linear status match is clearer.
   - Set `timeout_global(10s)`. ureq's default is **no timeout**, and an
     un-timed-out child holding a lock for 2 minutes is a real failure mode.
   - `GET $CLAUDE_STATUS_SPEND_URL` (default
     `https://api.anthropic.com/api/oauth/usage`) with
     `Authorization: Bearer <token>` and `Content-Type: application/json`.

   The whole TLS tree is **cold code on the render path** — a separate process
   during a refresh, never faulted in during a render. *Test-first:* against the
   stub server in step 9, never the real endpoint.

8. **`src/spend/refresh.rs` — the child.** Lock → **60-second dedupe** (if the
   cache was written under a minute ago, a sibling just ran; exit) → credentials
   → fetch → extract → atomic write → release in all paths. `mkdir -p` on the
   cache directory happens **before** the lock. The child loads the **user
   config layer only** — a repo-level `spend.refreshMinutes` therefore affects
   when a refresh is *triggered* but not the backoff arithmetic inside the
   child. It prints nothing, renders nothing, and always exits 0.

   Failure handling, with three corrections the contract omits:
   - **429** → `backoffUntil = now + min(refreshMinutes × 2^failures, 6h)` using
     the **already-incremented** failure count, so the first 429 gives 30
     minutes, not 15. Keep the last good `data`.
   - **401** → the token expired. Increment failures, keep the last good data.
   - **Network error / no credentials** → increment failures, keep the last good
     data. **Never clear a good value because one fetch failed.**
   - **`backoffUntil` is not carried forward.** Only the 200 branch writes `0`
     and only the 429 branch writes a real value; a network error or a 401 after
     a 429 leaves the key absent, which reads back as `0` and **erases the
     backoff**. Faithful, and load-bearing for anyone comparing behaviour.
   - `plan` is refreshed even on failure — from `creds.plan` when credentials
     were found, else from the prior cache.

   *Test-first:* each failure mode against the stub; a 429 then a network error
   leaves `backoffUntil` at 0; a failed fetch preserves the prior `data`.

9. **The stub server.** A ~40-line `std::net::TcpListener` on `127.0.0.1:0` in a
   test thread, replying with canned HTTP/1.1 over **plain HTTP** — the endpoint
   is overridable and ureq speaks plain HTTP, so **no TLS in tests**. Six cases:
   200 with a `spend` block, 200 with `extra_usage`, 200 with neither, 401, 429,
   and a connection refusal. *Test-first:* all six drive `refresh.rs` end to end
   and assert the resulting cache file.

10. **`src/debug.rs` — the narration.** Every gate above was a silent `return`
    in the JS, and before `--debug` existed a Max account with a perfect token
    was indistinguishable from a broken one. `--debug` narrates to **stderr**
    only, and must compose: `--version --debug` still prints a bare version, and
    a render with `--debug` still prints the same bytes on stdout.

    It prints: the cache path and endpoint in use; the prior cache's age, plan
    and failure count; a held or stale lock; the 60-second dedupe; **where**
    credentials were found (never the token); the HTTP status; what was
    extracted; and, last, a verdict — `WILL RENDER` with the figure, or which
    gate stops it. Reproduce the verdict line: it is the single most useful
    thing the tool prints. *Test-first:* stdout is byte-identical with and
    without `--debug`; the verdict line names the correct gate for each of the
    four; no token ever appears on stderr.

11. **Wire the segment.** Replace the `None` stub in `render/segments.rs` with
    the real builder, and confirm the golden tests from plan 1 still pass with
    `spend` gated off. *Test-first:* the plan 1 goldens are unchanged; a new
    golden covers the rendering case.

12. **Benchmark.** `hyperfine` the render path before and after `ureq` landed.
    This number decides whether the single-binary bet was right — if adding TLS
    moves the render p50 at all, the demand-paging assumption is wrong and the
    refresh should be split into a second binary. *Test-first:* not a test; a
    recorded measurement in the cycle's journal, and a gap entry if p50
    regressed.

## Acceptance criteria (from blueprint)

Derived from [the behaviour contract](../spec/statusline-behaviour.md) §7 and
its §10 Phase-3 verification clause; it carries no `Acceptance` blocks.

- [ ] Given `spend` is absent from the resolved `lines`, when the binary
      renders, then the cache file is never opened and no child process is
      spawned — from [contract §7, gate 1](../spec/statusline-behaviour.md)
- [ ] Given a cache older than `refreshMinutes`, when the binary renders, then
      it draws the cached value immediately and spawns a detached child without
      waiting for it — from [contract §7](../spec/statusline-behaviour.md)
- [ ] Given any render at all, when it completes, then no network request was
      made by the rendering process — from
      [contract §1, invariant 2](../spec/statusline-behaviour.md)
- [ ] Given `refreshMinutes: 0`, when the binary renders, then no child is
      spawned but the cached value is still drawn — from
      [contract §7](../spec/statusline-behaviour.md)
- [ ] Given a lock file under 2 minutes old, when `--refresh-spend` runs, then
      it exits without fetching; and given one older than 2 minutes, it takes
      the lock over — from [contract §7](../spec/statusline-behaviour.md)
- [ ] Given a cache written under 60 seconds ago, when `--refresh-spend` runs,
      then it exits without fetching — from
      [contract §7](../spec/statusline-behaviour.md)
- [ ] Given a 200 response carrying `spend.limit.amount_minor`, and separately
      one carrying only `extra_usage.monthly_limit`, and separately one carrying
      neither, when `--refresh-spend` runs, then the cache holds the extracted
      figures, the extracted figures, and `data: null` respectively — from
      [contract §7](../spec/statusline-behaviour.md)
- [ ] Given a 429, when `--refresh-spend` runs, then `backoffUntil` is set to at
      least 30 minutes ahead and the previously cached `data` is preserved —
      from [contract §7](../spec/statusline-behaviour.md)
- [ ] Given a 401 or a refused connection, when `--refresh-spend` runs, then
      `failures` increments and the previously cached `data` is preserved — from
      [contract §7](../spec/statusline-behaviour.md)
- [ ] Given a successful fetch on a Max account under `show: "auto"`, when the
      binary renders, then the segment is hidden and `--debug` names gate 4 as
      the reason — from [contract §7](../spec/statusline-behaviour.md)
- [ ] Given `--debug` on any invocation, when it runs, then stdout is
      byte-identical to the same invocation without it, and the access token
      appears nowhere on stderr — from
      [contract §§5, 7](../spec/statusline-behaviour.md)
- [ ] Given a live machine, when `claude-status --refresh-spend --debug` is run
      by hand once, then the credential path resolves and the verdict line
      prints — from [contract §10, Phase 3](../spec/statusline-behaviour.md)

## Risks / drift

- **The renamed cache is a deliberate compatibility break.** Existing installs
  re-fetch once on first run — one request, harmless by the contract's own
  reasoning. But anyone with `$AI_PLUGINS_SPEND_CACHE` exported in their shell
  profile will find it silently ignored. **Resolving step:** document the rename
  in the README during [plan 4](./2026-08-19-1403-distribution.md), and have
  `--debug` print the resolved cache path so the surprise is one command away
  from diagnosis.
- **The contract's §7 is wrong on the backoff and the stretch.** It states the
  first 429 gives `refreshMinutes × 2^failures` without saying `failures` is
  already incremented, omits that `backoffUntil` is not carried forward, and
  gives the 24-hour stretch without its four conditions. Steps 4 and 8 encode
  the corrected behaviour. **Resolving step:** amend
  `docs/spec/statusline-behaviour.md` §7 in this cycle.
- **The real endpoint is never exercised in CI**, only the stub. The one live
  check is manual and on a developer machine. A schema change upstream would
  surface as `data: null` and a silently hidden segment — the exact pathology
  `--debug` exists for.
- **The keychain is not scoped by `$HOME`.** A test with a fake home can still
  trigger a real credential read and a real network call if a stale cache spawns
  a refresh. Plan 1 step 12 already neutralises this three ways; do not weaken
  it when adding spend tests. A stray real fetch in CI is both a privacy leak
  and a 429 worn for half an hour.
- **`ring` needs a C toolchain.** ureq's rustls feature pulls it in. Native
  builds are fine; cross-compiling to `aarch64-unknown-linux-gnu` from macOS
  will need `cross` or `cargo-zigbuild`. Surfaced here, resolved in
  [plan 4](./2026-08-19-1403-distribution.md).
- **`process_group(0)` is not `setsid()`.** It is one step short — the child
  keeps its controlling terminal. Judged sufficient because the lock's 2-minute
  staleness takeover already covers a killed child. If abandoned lock files show
  up after terminal closes, adding `libc` for a `pre_exec` `setsid` is a
  five-line, well-contained change.

## Out of scope for this cycle

- Migrating an existing `~/.cache/ai-plugins/spend.json` — decided against; a
  re-fetch is one request.
- Renaming `$AI_PLUGINS_USAGE_DIR` — a cross-repo contract, explicitly
  unchanged.
- `rustls-platform-verifier` (using the macOS keychain trust store, which helps
  behind a corporate MITM proxy) — a one-line feature swap if someone asks.
- Splitting the refresh into a second binary — only if step 12's benchmark shows
  a render regression.
- `--info` — [plan 4](./2026-08-19-1403-distribution.md), though it consumes
  this cycle's verdict function.
