# Plan: main-bar — 2026-08-19

## Slice

The main bar — §§1–6 and §8 of
[the behaviour contract](../spec/statusline-behaviour.md): input parsing, the
two-layer config merge, colour resolution, the powerline renderer, ten of the
eleven segments, the formatting helpers, git resolution, and the usage mirror.

Plan 1 of 4 — no prerequisites; required by
[`subagent-panel`](./2026-08-19-1401-subagent-panel.md) and
[`spend`](./2026-08-19-1402-spend.md), which both build on the config, colour,
powerline and formatting layers this cycle lands.

The `spend` segment is deliberately excluded and ships as a builder that always
returns `None`; the whole subsystem is [plan 3](./2026-08-19-1402-spend.md).

> **Note on `covers:`.** The contract is a behaviour spec at
> `docs/spec/statusline-behaviour.md`, not a `docs/blueprint/` flow — this repo
> has no blueprint yet. See [Risks / drift](#risks--drift).

## Target state (per blueprint)

A `claude-status` binary that reads a main-bar JSON payload on stdin and writes
two powerline lines to stdout in 1–2 ms, per §§1–6 and §8 of the contract.

Deviations from the contract document and from the JS, each decided deliberately
and each carrying a step below:

| Decision             | Contract says                                                 | This plan does                                                              |
| -------------------- | ------------------------------------------------------------- | --------------------------------------------------------------------------- |
| Defaults             | Two file layers; a machine with no config renders blank       | Three layers, `embedded → ~/.config → <repo>/.config`                       |
| Git budget           | "two subprocesses, 250 ms each"                               | Up to four subprocesses on two threads under **one shared 250 ms deadline** |
| Missing symbol key   | (unstated; JS renders the literal text `undefined`)           | Renders `""`                                                                |
| Malformed hex colour | (unstated; JS parses `"#12345g"` leniently to a wrong colour) | Falls back to `palette.white`                                               |
| Version              | (unstated)                                                    | `6.0.0`, continuing from the JS's 5.1.0                                     |

Everything else is faithful, **including behaviours that look like bugs**:
`humanTokens(999999)` stays `"1000k"`, `toFixed` rounds half-up, a binary-only
diff renders clean, and a detached HEAD containing `ref: refs/tags/v1` renders
the branch `ref: re`.

## Delta — ordered steps

1. **Pin the crate shape and profile.** `Cargo.toml`: version `6.0.0`, a `[lib]`
   (`claude_status`) alongside `[[bin]]` (`claude-status`) — an integration test
   in `tests/` cannot link a bin target, so golden tests need the lib.
   Dependencies, each named here because the plan's approval gate is where they
   are consented to:
   - `serde_json` **1.0.151**, `default-features = false`,
     `features = ["std", "preserve_order"]` — untyped `Value` parsing, the deep
     merge, and cache/mirror serialisation. **No `serde` derive**: every field
     is optional, so derives buy nothing and cost the proc-macro.
     `preserve_order` (via `indexmap`) is what keeps "statuses are tried in
     config order" true.
   - `regex-lite` **0.1.9** — `worktreePattern` and, in plan 2,
     `subagent.statuses[].match`. The full `regex` crate is ~1.5 MB and builds a
     DFA on a per-render path.
   - `tempfile` **3.x**, `[dev-dependencies]` only — throwaway `$HOME` for e2e
     tests.

   `[profile.release]`: `opt-level = "s"`, `lto = "fat"`, `codegen-units = 1`,
   `strip = "symbols"`, and **`panic = "unwind"` with a comment saying why** —
   under `abort`, `catch_unwind` cannot catch and the bar goes blank, which
   breaks the contract's third invariant. *Test-first:*
   `tests/defaults_integrity.rs` fails to compile (no lib target).

2. **Guard the defaults asset.** `src/config/defaults.rs` exposes
   `pub const DEFAULTS_JSON: &str = include_str!("../../assets/claude-status.defaults.json")`.
   *Test-first:* `tests/defaults_integrity.rs` parses `DEFAULTS_JSON` and
   asserts all 39 glyph keys equal their codepoints written as `\u{…}` escapes
   (the table in contract §3), the 10 palette triples, `gauge.width == 10`,
   `subagent.descBudgetFraction == 0.45`, and the default `lines`. The *test* is
   safe to retype; the asset is not. This is the mechanical form of the
   contract's "verify by rendering, never by reading a diff".

3. **`src/json.rs` — Value helpers and the merge.** `opt_str`/`opt_f64`/
   `opt_obj`/`opt_arr`, `read_json_file -> Option<Value>` (every error becomes
   `None`, silently — a syntactically invalid config layer is ignored, not
   fatal), `write_json_atomic` (temp `<file>.<pid>.tmp` + rename), and
   `deep_merge`. *Test-first:* `deep_merge` unit tests — objects recurse key by
   key; arrays and scalars replace wholesale; an explicit `null` in the override
   **replaces**; `__proto__` / `constructor` / `prototype` are skipped **at
   every depth**, not just the top.

4. **`src/fmt.rs` and `src/time.rs` — the pure helpers.** These are the densest
   unit-test target in the crate and nothing renders before they pass.
   - `to_fixed(n, digits)` rounding **half away from zero on the decimal
     expansion**, matching JS `toFixed`. Rust's `{:.N}` rounds half-to-even and
     would render `0.25` as `0.2` where JS gives `0.3`.
   - `human_tokens`, `human_duration`, `human_reset_in`, `gauge`, `money`.
   - `now_ms()` and `to_epoch_ms(&Value)`: numbers `> 1e12` are millis,
     otherwise seconds×1000 (**including 0 and negatives**); strings parse an
     RFC 3339 subset plus bare `YYYY-MM-DD` via `days_from_civil`; **numeric
     strings return `None`**, because JS `Date.parse("1774200000")` is `NaN`.

   *Test-first:* the boundary table — `human_tokens(999999) == "1000k"` (**not**
   `"1M"`), `(1_000_000) == "1M"`, `(1_250_000) == "1.3M"`, `(999) == "999"`,
   `(None) == "?"`; `human_duration(33_540_000) == "9hr 19m"`,
   `(3_600_000) == "1hr 0m"`, `(252_000) == "4m 12s"`, `(999) == "0s"`;
   `human_reset_in` → `"now"` at or past zero, `"4h36m"`, `"1h06m"` (minutes
   zero-padded, hours not), `"5m"` (unpadded), `"5d0h"` (days drop minutes);
   `gauge(26, 10)` → 3 filled, `gauge(-5)` → empty, `gauge(150)` → full;
   `money(7593, 2) == "$75.93"`, `money(15000, 2) == "$150"`,
   `money(1234, 3) == "$1.23"`.

5. **`src/config/` — the three layers.** `layers.rs` merges
   `embedded → $HOME/.config/claude-status.json → <repo-root>/.config/claude-status.json`.
   `$HOME` is read directly and joined with `.config` literally — **not**
   `dirs::config_dir()`, which resolves to `~/Library/Application Support` on
   macOS and would break every existing install. `color.rs` resolves palette
   name → `#rgb`/`#rrggbb` → `[r,g,b]` → `palette.white` → `[251,241,199]`, and
   emits `\x1b[38;2;R;G;Bm` / `\x1b[48;2;R;G;Bm`. `matcher.rs` compiles a
   pattern with no metacharacters beyond `|` — which describes every shipped
   pattern — to lowercased literals matched by `contains`, falling back to
   `regex-lite` with `case_insensitive(true)` otherwise. *Test-first:* layer
   precedence (repo beats user beats embedded); a malformed user layer is
   ignored rather than fatal; `"#abc"` expands by doubling; `"#12345g"` yields
   white (**deviation** — the JS yields a wrong colour); an unresolvable name
   yields white; a `worktreePattern` `regex-lite` rejects falls back to the
   literal default and warns on **stderr**.

6. **`src/render/powerline.rs` — the seam logic.** Pure: `&[Segment] -> String`.
   The SGR emission order differs between branches and is load-bearing:

   | Piece        | Emission                                                        |
   | ------------ | --------------------------------------------------------------- |
   | cap          | `fg(seg[0].bg)` `cap` `RESET` — no background                   |
   | body         | `bg` `fg` `[bold]` `" " text " "` `RESET`                       |
   | same-bg seam | `bg(next.bg)` `fg(thinFg)` `sepThin` `RESET` — **bg before fg** |
   | diff-bg seam | `fg(this.bg)` `bg(next.bg)` `sep` `RESET` — **fg before bg**    |
   | close        | `fg(last.bg)` `sep` `RESET` — no background, **unconditional**  |

   `RESET` (`\x1b[0m`) follows *every* fragment, so bold never leaks and a
   mid-line truncation by Claude Code cannot bleed colour into the TUI.
   Backgrounds compare by resolved RGB, so `"blue"` and `"#458588"` are the same
   background and take the thin seam. *Test-first:* golden strings for two
   adjacent same-bg segments (the `sepThin` path), a one-segment row (which
   still gets a closing separator), and an empty row (which renders `""`).

7. **`src/payload.rs` — normalisation.** `Value` in, plain owned structs out, so
   the renderer below is pure. Every ladder from contract §2, plus the `??`/`||`
   distinctions the contract omits: `total_input_tokens: 0` is **kept** as `0`,
   but a `current_usage` sum of exactly `0` **falls through** to the derived
   branch; `gauge.width: 0` means 10; `spend.refreshMinutes: 0` genuinely means
   zero. `model` and `effort` each accept an object or a bare string; a trailing
   parenthetical is stripped (`"Opus 5 (1M context)"` → `"Opus 5"`), on the `id`
   branch too. `rate_limits.seven_day` **or** `weekly`; `five_hour` has no
   alias. *Test-first:* one case per ladder rung, plus malformed stdin parsing
   to an empty object rather than erroring — a bad payload renders a normal bar
   of defaults, it does **not** trigger the fallback.

8. **`src/proc.rs` and `src/git.rs` — bounded git.** Root and branch come from
   the filesystem: walk up at most 40 iterations for `.git`; a directory means
   read `.git/HEAD`; a file means parse `gitdir: <path>` (resolved relative to
   the directory *containing* `.git`, lexically normalised) and read `HEAD`
   there. Reproduce the JS's try-block scoping: a `.git` directory whose `HEAD`
   is unreadable does **not** stop the walk — it continues to the parent, so a
   nested repo with a broken HEAD reports the outer repo.

   `proc.rs::run_bounded` spawns with stdin closed, stdout piped, stderr null,
   moves the pipe into a reader thread, and uses `recv_timeout`; on timeout it
   kills and reaps. **Not `wait-timeout`**, which installs a process-global
   `SIGCHLD` handler — hostile in a 1 ms process that also spawns a deliberately
   unreaped detached child — and which does not drain stdout, so a large
   `git diff --numstat` can deadlock on a full pipe.

   **Deviation:** the ahead pipeline (`rev-list --count @{upstream}..HEAD`) and
   the dirty pipeline (`diff --numstat HEAD`, falling back to `--cached`, then
   `ls-files --others --exclude-standard`) run on two threads under **one shared
   250 ms deadline**. The JS runs up to four subprocesses sequentially at 250 ms
   each — a ~1 s worst case on a bar that must never block.

   Faithful details: binary files report `-` in numstat and are **skipped on
   both sides**, so a binary-only change renders clean; untracked files add
   exactly `+1` to additions regardless of count; if `ls-files` fails the whole
   dirty marker is `""` even though numstat succeeded; markers are `±` / `+` /
   `-` / empty. `worktree_subpath` splits cwd on `/`, drops empty components,
   takes everything after the **last** component matching `worktreePattern`
   case-insensitively, and yields nothing when that match is the final
   component. *Test-first:* fixture `.git` trees under a `tempfile::TempDir` —
   plain repo, worktree pointer file, relative `gitdir:`, detached HEAD (7
   chars), unreadable HEAD inside a nested repo, and a 41-level walk that gives
   up.

9. **`src/render/segments.rs` and `main_bar.rs` — ten segments.** Styling
   resolves inline override → `segments.<id>` default → `bg: "blue"`,
   `fg: defaultFg`, `bold: false`. An entry object is keyed by `name` **or**
   `id`. A builder returning "no data" omits its segment entirely; a row whose
   segments all omit is dropped, and surviving rows join with `\n`. An unknown
   segment id writes exactly `statusline: unknown segment "<id>"\n` to
   **stderr** and omits. A panicking builder omits that one segment, silently.

   Texts corrected against the JS where the contract's table is wrong:
   - `rl5h`/`rl7d` — `{win5h} 7.0% {reset} 4h36m`, with a **space before** the
     reset glyph. The reset half is omitted when the timestamp does not parse.
   - `branch` — the worktree prefix is `{worktree}` *then* `{branch}`, then the
     ahead marker, then the dirty marker, each preceded by exactly one space and
     each conditional.
   - `duration` — omitted only when absent; `0` renders `{duration} 0s`.
   - `context` — with no data at all, `{context} ▱▱▱▱▱▱▱▱▱▱ ?/? (0%)`.
   - `cost` — `{cost} $0.00` when absent; the symbol is two codepoints (U+23F1
     U+FE0F).
   - `model` — falls back to `Claude`, including when the display name is `""`.
   - `spend` — a stub returning `None`. Wired in plan 3.

   **Deviation:** a symbol key missing from the merged config renders `""`, not
   the literal text `undefined`. With the embedded layer this is unreachable in
   practice; it is a guard, not a behaviour. *Test-first:* one golden per
   segment plus the omission cases.

10. **`src/usage.rs` — the mirror.** Contract §8, a hard cross-repo contract
    with `ai-plugins`, so byte-compatibility is the acceptance bar. Enabled only
    when `$AI_PLUGINS_USAGE_DIR` is set — **this env var name does not change**.
    Expand a leading `~`, `$HOME` or `${HOME}` with the JS's loose pattern
    (which also accepts `${HOME` and `$HOME}`). Write `<dir>/<session_id>.json`
    atomically, best-effort: a failure here must never affect the rendered line.
    Runs before anything that can fail, and is not gated on the layout or on
    git. *Test-first:* the nine keys in order — `sessionId`, `ts`, `ctxPct`,
    `ctxUsed`, `ctxSize`, `fiveHourPct`, `fiveHourResetsAt`, `sevenDayPct`,
    `sevenDayResetsAt`; `resets_at` mirrored **raw** rather than normalised (the
    consumer does its own discrimination, and an ISO string must stay an ISO
    string); `ctxSize` **absent** rather than `null` when the payload carried no
    `context_window_size`, while the four rate-limit fields are present as
    `null`. Assert the filename does not collide with `<session>.state.json`,
    which `context-caps.js` owns.

11. **`src/lib.rs`, `src/cli.rs`, `src/main.rs` — the boundary.** `cli.rs` is a
    hand-rolled scan of `env::args_os()`: `--version` checked **first** (the
    installer distinguishes an installed binary from a bundled one by the shape
    of that answer), then `--refresh-spend`, with `--debug` a boolean modifier
    on any of them. No `clap` — a dependency that writes to stdout when it
    dislikes an argument is a liability against the "stdout is the bar"
    invariant, and `--version` comes from `env!("CARGO_PKG_VERSION")` so there
    is no second version constant to keep in sync.

    `lib.rs` is the **only** place anything writes to stdout, and it writes only
    after the renderer has returned a complete `String`. Streaming segments
    could emit half a bar and *then* the fallback, which is worse than either.
    `catch_unwind` wraps the render; on unwind, write the literal `⚡ Claude`
    (U+26A1, space, `Claude`) and put the real error on stderr. *Test-first:*
    `--version` prints `6.0.0\n` and **nothing else**; `--version --debug` still
    prints a bare version; a render emits **no trailing newline**; a forced
    panic yields the fallback on stdout and a message on stderr; `tests/e2e.rs`
    captures both streams separately and asserts stdout holds only the bar.

12. **Golden tests and the render harness.** `now_ms` is a **field** on the
    facts struct, not a call — the §12 fixture's `resets_at` values are already
    in the past, so without an injected clock the reset halves render `now` and
    the goldens rot. `tests/golden.rs` builds facts literals, calls
    `render_main(&Facts, &Config) -> String`, and compares against
    `tests/golden/*.txt`; on mismatch it prints both sides through
    `.escape_debug()` so CI shows `\u{1b}[48;2;69;133;136m` rather than
    invisible bytes. `UPDATE_GOLDEN=1` rewrites them.

    e2e cases neutralise the contract's §11 hazard three ways at once, because
    the macOS keychain is **not** scoped by `$HOME` and a stray real fetch is
    both a privacy leak and a 429 worn for half an hour:
    `spend.refreshMinutes = 0` in the fake config, `CLAUDE_STATUS_SPEND_URL`
    pointed at a closed port, and a pre-seeded fresh cache file. *Test-first:*
    the §12 main-bar fixture, `spend` absent from the cache, rendering
    byte-identically to `node statusline` under the same fixture and a matching
    seeded config.

13. **Wire the harness.** Add a `code:lint` mise task running
    `cargo clippy -- -D warnings` and a `code:test` task running `cargo test`,
    and uncomment the lint line in `code/all`. The repo currently has no Rust
    lint or test task, so nothing above is enforced by `pre-commit` until this
    lands. *Test-first:* `mise run code:all` fails on a deliberately introduced
    clippy warning, then passes once reverted.

## Acceptance criteria (from blueprint)

Transcribed from [the behaviour contract](../spec/statusline-behaviour.md); it
has no `Acceptance` blocks, so these are derived from its invariants and its §10
Phase-1 verification clause.

- [ ] Given the §12 main-bar fixture on stdin and a `$HOME` seeded with the
      shipped defaults, when the binary runs with `spend` absent from the cache,
      then stdout is byte-identical to `node statusline` under the same inputs —
      compared with `diff`, not by eye — from
      [contract §10, Phase 1](../spec/statusline-behaviour.md)
- [ ] Given any payload, valid or malformed, when the binary renders, then
      stdout contains only the bar and every diagnostic is on stderr — from
      [contract §1, invariant 1](../spec/statusline-behaviour.md)
- [ ] Given a render, when it completes, then no network call was made, no
      unbounded subprocess ran, and total git subprocess time did not exceed 250
      ms — from [contract §1, invariant 2](../spec/statusline-behaviour.md)
- [ ] Given a payload that makes a segment builder panic, when the binary
      renders, then a usable line still reaches stdout and the error is on
      stderr — from [contract §1, invariant 3](../spec/statusline-behaviour.md)
- [ ] Given a config layer that is syntactically invalid JSON, when the binary
      renders, then that layer is ignored and the render succeeds — from
      [contract §3](../spec/statusline-behaviour.md)
- [ ] Given a `lines` entry naming an unknown segment, when the binary renders,
      then `statusline: unknown segment "<id>"` is on stderr, the segment is
      omitted, and the exit code is 0 — from
      [contract §4](../spec/statusline-behaviour.md)
- [ ] Given `$AI_PLUGINS_USAGE_DIR` is set and a payload carrying context and
      rate-limit figures, when the binary renders, then
      `<dir>/<session_id>.json` matches the §8 field names and layout, and
      `context-caps.js` reads it unchanged — from
      [contract §8](../spec/statusline-behaviour.md)
- [ ] Given `$AI_PLUGINS_USAGE_DIR` is unset, when the binary renders, then no
      file is written — from [contract §8](../spec/statusline-behaviour.md)
- [ ] Given `--version`, when the binary runs, then stdout is exactly `6.0.0\n`
      and nothing else, whether or not `--debug` is also passed — from
      [contract §5](../spec/statusline-behaviour.md)
- [ ] Given a cold start on a machine with no `~/.config/claude-status.json`,
      when the binary renders, then a full default bar is drawn — **deviation
      from the JS**, which renders blank; see Risks / drift

## Risks / drift

- **There is no blueprint.** `docs/blueprint/` is empty and `.config/vwf.yaml`
  carries no coverage stamp, so `covers:` points at
  `docs/spec/statusline-behaviour.md` — a behaviour spec, not a flow contract.
  `/vwf:execute`'s Reconcile stage cannot stamp `implementation:` on a doc with
  no vwf frontmatter, and the acceptance criteria above are derived rather than
  transcribed. **Resolving step:** run `/vwf:product` → `/vwf:architecture` →
  `/vwf:blueprint` and re-point `covers:`, or accept this cycle as
  blueprint-exempt with the deviation recorded here. This is a decision for the
  approval gate, not something to discover during execution.
- **The contract document is wrong in places.** Deep-reading the JS found errors
  in its §1 (two git subprocesses, actually up to four), its §4 segment table
  (`rl5h`/`rl7d` spacing, `duration` omission, the `branch` worktree prefix),
  and its §7 (the 24-hour stretch conditions). Steps 8 and 9 encode the
  corrected behaviour. **Resolving step:** amend
  `docs/spec/statusline-behaviour.md` in the same cycle so the contract and the
  code agree — the contract is never left contradicting shipped behaviour.
- **The defaults asset is irreplaceable.** 28 Nerd Font private-use codepoints
  that render as boxes or nothing in most editors and are silently dropped by
  copy-paste. It is now tracked, `-text -diff`, and dprint-excluded, and step 2
  guards it with a test. **Never** edit it through an editor buffer or let a
  formatter touch it.
- **The config file is renamed, which the contract advises against.** §3 says to
  keep the file name identical so existing users can point Claude at the new
  binary and see the same bar. This plan renames it to `claude-status.json` for
  consistency with the tool's identity, and
  [plan 4](./2026-08-19-1403-distribution.md) step 7 carries the migration —
  `--install` moves the old file, preserving the user's theming, and
  `--uninstall` puts it back. The binary itself only ever knows the new name, so
  no per-render stat is spent on a legacy path. **Consequence for this cycle's
  verification:** the `diff`-against-`node statusline` check must run in a
  controlled fixture directory with a seeded `$HOME`, *not* inside this repo —
  this repo's layer has already moved to `claude-status.json`, which the JS
  implementation will not read and the Rust one will, so `projectName` would
  differ and the comparison would fail for the wrong reason. Until the Rust
  binary ships, the JS bar shows `Project-Name` in this checkout; that is
  expected and resolves at cutover.
- **Embedded defaults are a behaviour change.** A user who deleted a key from
  their seeded config expecting it gone will get the default back. Judged
  clearly worth it: output is byte-identical for every install whose user file
  *is* the seeded defaults, which is all of them.
- **`opt-level = "s"` is a guess.** The compute is ~50 µs of string building; a
  smaller text segment should fault in faster. Benchmark `s` against `3` with
  `hyperfine` during step 12 and keep the winner — it is a one-word change.
- **`to_fixed` fidelity is untested against real inputs.** JS `toFixed` breaks
  ties upward; Rust `{:.N}` breaks to even. Reachable via
  `used_percentage: 0.25` or `total_cost_usd: 0.125`, but rare. If step 4's
  implementation proves fiddly, record the divergence rather than shipping a
  subtly wrong `to_fixed`.
